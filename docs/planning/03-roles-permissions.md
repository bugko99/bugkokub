# 03 — User Roles & Permissions
## ระบบรับเรื่องร้องเรียนศูนย์ดำรงธรรมจังหวัดศรีสะเกษ (DCMS)

> **Planning Only** — อ้างอิงจาก `docs/planning/01-system-overview.md` และ `02-requirements.md`

---

## 1. สรุป User Roles ในระบบ

ระบบ DCMS ถูกออกแบบให้รองรับการทำงานของกลุ่มบุคคลที่หลากหลาย โดยแบ่งระดับสิทธิ์ (Role-based Access Control - RBAC) ออกเป็น 6 กลุ่มหลัก เพื่อให้ครอบคลุมการทำงานตั้งแต่รับเรื่องไปจนถึงการบริหารจัดการระดับสูง

| Role | คำอธิบายบทบาท | สิทธิ์ที่ทำได้ (Permissions) | หน้าจอที่เข้าถึงได้ | ข้อมูลที่มองเห็นได้ | ข้อจำกัดของ Role |
|---|---|---|---|---|---|
| **1. Super Admin** <br/>*(ผู้ดูแลระบบ)* | ดูแลรักษาระบบ จัดการผู้ใช้งาน และตั้งค่าพื้นฐานของระบบ | - สร้าง/แก้ไข/ลบ/ระงับ บัญชีผู้ใช้<br/>- กำหนด Role ให้ผู้ใช้อื่น<br/>- จัดการ Master Data (ประเภทเรื่อง, SLA, หน่วยงาน)<br/>- ดู Audit Log | - User Management<br/>- Master Data Settings<br/>- System Audit Log | มองเห็นข้อมูลทั้งหมดในระบบ รวมถึง Log การเข้าใช้งาน และการตั้งค่าเชิงลึก | **ไม่ควร**เข้าไปก้าวก่ายกระบวนการรับเรื่องหรือแก้ไขสถานะเรื่องร้องเรียนโดยตรง (เพื่อการแบ่งแยกหน้าที่ - Segregation of Duties) |
| **2. หัวหน้าศูนย์ดำรงธรรม** <br/>*(Supervisor)* | ควบคุมตรวจสอบการทำงานของเจ้าหน้าที่ และพิจารณาปิดเรื่อง/ยกเลิกเรื่อง | - สิทธิ์ทั้งหมดของเจ้าหน้าที่ศูนย์ฯ<br/>- กดอนุมัติ **"ปิดเรื่อง" (Close)** หรือ **"ยกเลิกเรื่อง" (Cancel)**<br/>- ดูรายงานเชิงลึกและสถิติการทำงานของเจ้าหน้าที่ | - Dashboard (ระดับศูนย์ฯ)<br/>- Reports Export<br/>- รายการเรื่องทั้งหมด<br/>- Notification | มองเห็นเรื่องร้องเรียนทั้งหมดที่เข้ามายังศูนย์ดำรงธรรม และสถิติการทำงานย้อนหลัง | ไม่สามารถลบเรื่องร้องเรียนออกจากระบบได้ (ทำได้เพียงยกเลิก) และไม่สามารถตั้งค่าผู้ใช้หรือระบบได้ |
| **3. เจ้าหน้าที่ศูนย์ดำรงธรรม** <br/>*(Officer)* | ด่านหน้าผู้รับเรื่อง บันทึกข้อมูล ตรวจสอบ และส่งต่อให้หน่วยงาน | - บันทึกเรื่องร้องเรียนใหม่ (Walk-in, โทรศัพท์, ฯลฯ)<br/>- แก้ไขข้อมูลเรื่องร้องเรียน<br/>- เปลี่ยนสถานะ และ **"ส่งต่อ" (Forward)** เรื่อง<br/>- บันทึกความคืบหน้า (Internal/Public Note) | - รายการเรื่องร้องเรียน<br/>- แบบฟอร์มรับเรื่อง<br/>- รายละเอียดเรื่อง<br/>- Notification | เห็นเรื่องร้องเรียนทั้งหมดที่เข้ามายังศูนย์ดำรงธรรม และข้อมูลผู้ร้อง | ไม่สามารถ "ปิดเรื่อง" หรือ "ยกเลิกเรื่อง" ได้ด้วยตนเอง (ต้องผ่านหัวหน้า) และลบข้อมูลไม่ได้ |
| **4. หน่วยงานที่รับผิดชอบ** <br/>*(Agency Officer)* | เจ้าหน้าที่จากหน่วยงานภายนอก/แผนกอื่น ที่รับเรื่องไปแก้ไข | - กด **"รับเรื่อง" (Acknowledge)** เมื่อมีการส่งต่อมา<br/>- บันทึกความคืบหน้าการทำงาน<br/>- แนบไฟล์หลักฐานผลการดำเนินการ<br/>- เปลี่ยนสถานะเป็น "ดำเนินการแล้ว / รอตรวจสอบ" | - รายการเรื่อง (เฉพาะของหน่วยงานตนเอง)<br/>- รายละเอียดเรื่อง (เฉพาะที่ได้รับมอบหมาย)<br/>- Notification | **มองเห็นเฉพาะเรื่องที่ถูก "ส่งต่อ" มายังหน่วยงานของตนเองเท่านั้น** | มองไม่เห็นเรื่องของหน่วยงานอื่น และ **ไม่สามารถ "ปิดเรื่อง" ได้เอง** (ต้องส่งเรื่องกลับมาให้ศูนย์ดำรงธรรมเป็นผู้พิจารณาปิด) |
| **5. ผู้บริหารจังหวัด** <br/>*(Executive)* | ผู้ว่าราชการจังหวัด หรือรองผู้ว่าฯ ที่ต้องการดูภาพรวมเพื่อการบริหารจัดการ | - เรียกดู Dashboard สถิติภาพรวม<br/>- เรียกดูรายงานเรื่องที่ค้างชำระ (Overdue)<br/>- ค้นหาและดูรายละเอียดเรื่องร้องเรียน (Read-only) | - Executive Dashboard<br/>- Reports Summary<br/>- ค้นหาเรื่องร้องเรียน | มองเห็นข้อมูลสถิติภาพรวมทั้งหมด จำนวนเรื่องแยกตามอำเภอ/หน่วยงาน/ประเภท และเรื่องที่ล่าช้า | **ไม่มีสิทธิ์แก้ไขหรืออัปเดตข้อมูลใดๆ ในระบบ** (Read-only access) เพื่อป้องกันการแก้ไขข้อมูลโดยไม่ตั้งใจ |
| **6. ประชาชนผู้ร้องเรียน** <br/>*(Citizen)* | ผู้ใช้งานทั่วไป (ไม่ต้อง Login) ยื่นเรื่องและติดตามความคืบหน้า | - ยื่นเรื่องร้องเรียนผ่านฟอร์มออนไลน์<br/>- แนบไฟล์หลักฐาน<br/>- ตรวจสอบสถานะการดำเนินงาน (Track Status) | - Landing Page<br/>- ฟอร์มยื่นเรื่องออนไลน์<br/>- หน้าตรวจสอบสถานะ (Tracking) | **เห็นเฉพาะข้อมูลเรื่องร้องเรียนของตนเอง** โดยใช้ "หมายเลขเรื่อง" + "Tracking Code" ในการค้นหา | ไม่มีบัญชีผู้ใช้ในระบบ, มองไม่เห็น "Internal Notes" ของเจ้าหน้าที่, และแก้ไขข้อมูลไม่ได้หลังจากยื่นเรื่องไปแล้ว |

## 2. การจัดการสิทธิ์เชิงลึก (Detailed Access Matrix)

เพื่อความชัดเจนในการนำไปเขียนโค้ด การเข้าถึงข้อมูลของแต่ละฟังก์ชันจะถูกแบ่งตามตารางนี้:

| ฟังก์ชันการทำงาน (Feature) | Super Admin | Supervisor | Officer | Agency Officer | Executive | Citizen (No Login) |
|---|:---:|:---:|:---:|:---:|:---:|:---:|
| **ยื่นเรื่องร้องเรียนใหม่** | - | Create | Create | - | - | Create |
| **ดูรายการเรื่องร้องเรียน** | View All | View All | View All | View Own* | View All | View Specific** |
| **แก้ไขข้อมูลเรื่องร้องเรียน** | - | Update | Update | - | - | - |
| **ส่งต่อเรื่อง (Forward)** | - | Update | Update | - | - | - |
| **รับเรื่องไปดำเนินการ (Ack)** | - | - | - | Update | - | - |
| **บันทึกความคืบหน้า (Progress)**| - | Create | Create | Create | - | - |
| **บันทึกโน้ตภายใน (Internal)** | - | Create | Create | - | - | - |
| **ปิดเรื่อง (Close) / ยกเลิก** | - | Update | - | - | - | - |
| **ดู Dashboard / รายงาน** | View | View | - | - | View | - |
| **จัดการ User & Role** | CRUD | - | - | - | - | - |
| **จัดการ Master Data** | CRUD | - | - | - | - | - |
| **ดู Audit Log** | View | - | - | - | - | - |

*( * View Own = เห็นเฉพาะเรื่องที่หน่วยงานตนเองได้รับมอบหมาย )*  
*( ** View Specific = เห็นเฉพาะเรื่องที่มีรหัส Tracking Code ถูกต้อง )*

## 3. สรุปความจำเป็นของการออกแบบ Role แบบนี้

1. **การแบ่งแยกความรับผิดชอบ (Separation of Duties):** การแยก **Supervisor** ออกจาก **Officer** ช่วยป้องกันการปิดเรื่องโดยพลการหรือทุจริต ต้องมีกระบวนการตรวจสอบผลการดำเนินงานก่อนเสมอ
2. **ความปลอดภัยของข้อมูล (Data Privacy):** **Agency Officer** จะเห็นเฉพาะเรื่องของตนเอง ป้องกันหน่วยงานอื่นเข้าถึงข้อมูลที่ไม่เกี่ยวข้อง และ **Citizen** จะไม่เห็นข้อมูลภายใน (Internal Notes) ที่เจ้าหน้าที่คุยกัน
3. **การเข้าถึงของผู้บริหาร (Executive View):** ผู้บริหารมักไม่ค่อยต้องการใช้งานระบบลึกๆ การมี Role เป็น View-only จะช่วยป้องกันไม่ให้ระบบถูกแก้ไขโดยไม่ได้ตั้งใจ
4. **สะดวกสำหรับประชาชน:** การออกแบบให้ **Citizen** ไม่ต้อง Login ช่วยลดอุปสรรค (Friction) ในการร้องเรียน และใช้ Tracking Code เป็นกุญแจความปลอดภัยแทน Password

> **Note:** การออกแบบนี้ถือว่าครบถ้วนและครอบคลุมกระบวนการทางธุรกิจของระบบร้องเรียนศูนย์ดำรงธรรมทั้งหมด ไม่จำเป็นต้องเพิ่ม Role อื่นในระยะเริ่มต้น (Phase 1-3) แต่สามารถขยายเพิ่มได้ในอนาคต (เช่น Auditor ภายนอก) หากมีการร้องขอ
