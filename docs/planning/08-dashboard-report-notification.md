# 08 — Dashboard, Report & Notification Design
## ระบบรับเรื่องร้องเรียนศูนย์ดำรงธรรมจังหวัดศรีสะเกษ (DCMS)

> **Planning Only** — อ้างอิงจากเอกสาร Planning ก่อนหน้าทั้งหมด (01-07)

---

## 1. การออกแบบ Dashboard (Executive View)

Dashboard ถูกออกแบบมาเพื่อตอบคำถามเชิงบริหารให้ครบถ้วนภายในหน้าจอเดียว โดยประกอบด้วยองค์ประกอบต่างๆ ดังนี้:

### 🎛️ 1.1 Global Filters (ตัวกรองหลัก)
เพื่อให้ผู้บริหารสามารถเจาะจงข้อมูลได้ตามต้องการ:
- **Date Range:** กรองตามช่วงวันที่รับเรื่อง (เช่น วันนี้, 7 วันล่าสุด, เดือนนี้, ปีนี้, กำหนดเอง)
- **Agency:** เลือกดูเฉพาะบางหน่วยงาน
- **District:** เลือกดูเฉพาะบางอำเภอ

### 🃏 1.2 Dashboard Cards (ข้อมูลสรุปตัวเลข)
บัตรข้อมูลสรุปที่ด้านบนสุดของหน้าจอ เพื่อให้เห็นภาพรวมทันที:
1. **เรื่องร้องเรียนทั้งหมด (Total):** นับจำนวนเรื่องร้องเรียนทั้งหมดในช่วงเวลาที่เลือก
2. **เรื่องใหม่วันนี้ (New Today):** นับเรื่องที่ `created_at` คือวันปัจจุบัน
3. **อยู่ระหว่างดำเนินการ (In Progress):** นับเรื่องที่สถานะเป็น `FORWARDED` หรือ `IN_PROGRESS`
4. **เรื่องที่เกินกำหนด (Overdue Alert):** นับเรื่องที่สถานะไม่ถึง `RESOLVED` และ `due_date` น้อยกว่าวันปัจจุบัน (แสดงเป็นสีแดง)

*(ตัวอย่างสูตรคำนวณ: `SELECT count(id) FROM complaints WHERE status NOT IN ('CLOSED', 'RESOLVED', 'CANCELLED') AND due_date < CURRENT_DATE`)*

### 📊 1.3 Charts (กราฟสถิติ)
1. **แนวโน้มรายเดือน (Monthly Trend):** 
   - *ประเภท:* Line Chart
   - *คำถามที่ตอบ:* แนวโน้มเรื่องร้องเรียนเพิ่มขึ้นหรือลดลง?
   - *แกน X:* เดือน (Jan, Feb, ...) / *แกน Y:* จำนวนเรื่อง
2. **เรื่องร้องเรียนแยกตามประเภท (Top Categories):**
   - *ประเภท:* Pie Chart หรือ Bar Chart แนวตั้ง
   - *คำถามที่ตอบ:* ประเภทเรื่องใดพบมากที่สุด?
   - *สูตร:* `GROUP BY category_id ORDER BY count DESC LIMIT 5`
3. **เรื่องร้องเรียนแยกตามพื้นที่ (Top Districts):**
   - *ประเภท:* Map Heatmap หรือ Bar Chart แนวนอน
   - *คำถามที่ตอบ:* อำเภอใดมีเรื่องร้องเรียนมากที่สุด?
4. **สถานะการทำงานของหน่วยงาน (Agency Backlogs):**
   - *ประเภท:* Stacked Bar Chart
   - *คำถามที่ตอบ:* หน่วยงานใดมีเรื่องค้างมากที่สุด?
   - *แกน X:* ชื่อหน่วยงาน / *แกน Y:* จำนวนเรื่อง / *สี Stack:* (เกินกำหนดสีแดง, ใกล้กำหนดสีเหลือง, ปกติสีเขียว)

### 📋 1.4 Tables (ตารางข้อมูลเร่งด่วน)
- **รายการเรื่องร้องเรียนเกินกำหนด (Overdue List):** แสดงเรื่องที่หลุด SLA เพื่อให้ผู้บริหารติดตามเร่งรัดโดยตรง (แสดงเลขเรื่อง, ประเภท, หน่วยงานที่ถือเรื่อง, วันที่เกิน)

## 2. การออกรายงาน (Report Export)

ระบบรองรับการ Export ข้อมูลเพื่อนำไปทำรายงานประจำเดือนหรือประมวลผลต่อ:

1. **Format ที่รองรับ:** 
   - `CSV/Excel`: สำหรับให้เจ้าหน้าที่นำไปทำ Pivot หรือ Pivot Table ต่อ
   - `PDF`: สำหรับพิมพ์รายงานสรุปผลการปฏิบัติงานประจำเดือน
2. **สิ่งที่อยู่ใน Report (Data Fields):**
   - เลขรับเรื่อง, วันที่รับ, ช่องทางที่รับ
   - ประเภท, อำเภอที่เกิดเหตุ
   - สถานะปัจจุบัน, วันที่ครบกำหนด (Due Date)
   - หน่วยงานที่รับผิดชอบ
   - SLA Performance (เช่น สำเร็จตามกำหนด / ล่าช้า)
3. **รูปแบบรายงาน (Pre-defined Reports):**
   - **รายงานสรุปสถิติประจำเดือน:** สรุปยอดรวม แยกตามประเภทและหน่วยงาน
   - **รายงานสถานะงานค้าง (Backlog Report):** ลิสต์เฉพาะเรื่องที่ยังไม่ปิด
   - **รายงานการทำงานของหน่วยงาน:** ประเมิน SLA ของแต่ละหน่วยงาน (Agency Performance)

## 3. กฎการแจ้งเตือน (Notification Rules)

การแจ้งเตือน (In-app Notification) บนแถบ Topbar จะทำงานเมื่อเกิดเหตุการณ์ (Events) ดังต่อไปนี้:

| เหตุการณ์ (Trigger Event) | ผู้รับการแจ้งเตือน (Target Role) | เนื้อหาการแจ้งเตือน (Message) |
|---|---|---|
| **มีประชาชนยื่นเรื่องออนไลน์ใหม่** | Officer, Supervisor | มีเรื่องร้องเรียนใหม่รหัส [DCMS-0001] รอการตรวจสอบ |
| **Officer ส่งเรื่องให้หน่วยงาน (Forward)** | Agency Officer (เป้าหมาย) | ศูนย์ดำรงธรรมได้ส่งต่อเรื่อง [DCMS-0002] ให้หน่วยงานของท่าน |
| **Agency ปฏิเสธการรับเรื่อง (Reject)** | Officer | หน่วยงาน ก. ปฏิเสธการรับเรื่อง [DCMS-0002] กรุณาตรวจสอบ |
| **Agency บันทึกผลสำเร็จ (Resolved)** | Officer, Supervisor | หน่วยงาน ข. ดำเนินการเรื่อง [DCMS-0003] เสร็จสิ้นแล้ว รอการตรวจสอบ |
| **Agency บันทึกความคืบหน้า** | Officer | หน่วยงาน ข. อัปเดตความคืบหน้าเรื่อง [DCMS-0003] |
| **Supervisor สั่งปิดเรื่อง (Close)** | Agency Officer | ศูนย์ดำรงธรรมปิดเรื่อง [DCMS-0003] เรียบร้อยแล้ว |

## 4. กฎการแจ้งเตือนเรื่องกำหนดเวลา (SLA Alert Rules)

ระบบมี Cron Job รันทุกคืน (เวลา 01.00 น.) เพื่อตรวจสอบและอัปเดตสถานะ SLA และส่งแจ้งเตือน:

### ⚠️ ระดับที่ 1: ใกล้ครบกำหนด (Near Due)
- **เงื่อนไข:** `due_date - current_date <= 2 วัน` และสถานะไม่เท่ากับ `RESOLVED`, `CLOSED`, `CANCELLED`
- **ผู้รับแจ้งเตือน:** Officer (ของศูนย์ฯ) และ Agency Officer (ที่ถือเรื่องอยู่)
- **Message:** "เรื่องร้องเรียน [DCMS-0004] จะครบกำหนดดำเนินการในอีก 2 วัน"
- **UI Effect:** ป้ายสถานะจะแสดงแถบสีเหลือง (Warning)

### 🚨 ระดับที่ 2: เกินกำหนดเวลา (Overdue)
- **เงื่อนไข:** `current_date > due_date` และสถานะไม่เท่ากับ `RESOLVED`, `CLOSED`, `CANCELLED`
- **ผู้รับแจ้งเตือน:** Officer, Agency Officer และ **Supervisor (หัวหน้าศูนย์ฯ)**
- **Message:** "⚠️ เรื่องร้องเรียน [DCMS-0004] เกินกำหนดระยะเวลาดำเนินการแล้ว!"
- **UI Effect:** ป้ายสถานะจะแสดงแถบสีแดง (Critical/Overdue) และเรื่องจะโผล่ใน Dashboard ผู้บริหาร

### 🔄 ตัวอย่างการคำนวณ SLA (SLA Calculation Example)
- **ประเภทเรื่อง:** เรื่องเดือดร้อนรำคาญ (SLA = 15 วันราชการ)
- **วันที่รับเรื่อง:** 1 พฤศจิกายน 2024
- **วันหยุดที่คั่น:** เสาร์-อาทิตย์ (4 วัน)
- **การคำนวณ Due Date:** ระบบจะบวกไป 15 วันทำการ (ข้าม ส-อา และวันหยุดนักขัตฤกษ์ที่กำหนดใน Master Data) ทำให้ Due Date อาจตกวันที่ 22 พฤศจิกายน 2024
- **การตรวจเช็ค:** วันที่ 20 พฤศจิกายน (เหลือ 2 วัน) ระบบยิงแจ้งเตือน Near Due / วันที่ 23 พฤศจิกายน (เลยกำหนด) ระบบยิงแจ้งเตือน Overdue
